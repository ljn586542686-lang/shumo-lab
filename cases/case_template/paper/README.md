# paper

队员在这里准备各节正文、公式和图表。排版模块读取这些材料，`main.tex` 是编译入口。

在没有赛题、数据和模型输出前，不应填写结果分析和结论。

正式 writer manifest 必须使用 `controlled_writing_layer_v5`，同时提供
`argument_blueprint_contract_v1` 和 `STRONG_EVIDENCE_STORY`。逐问蓝图必须绑定实际研究
对象、模型、公式含义、假设、设问、结果、跨问依赖、失效条件与自选推理路径；字段非空但
正文不可见或引用不存在仍视为失败。蓝图不规定行文顺序，简单小问可声明 `SIMPLE`，混合
题型可声明 `MIXED/CUSTOM`。自动修复最多 2 次，之后必须人工审查。

每一问开场说明后、首组关键公式前必须放置与题目对象
直接对应的模型引导图，不得用抽象总览图或通用流程图替代。正式解释图总数不少于
`task_count+1`，至少一个重点任务另有过程或诊断图，并同时覆盖模型结构、中间过程、
结果诊断三类视觉。每张图
必须提出读者问题、给出正文可见结论，并连接模型/公式、中间状态和最终结果中的至少两层。
图数不足、只给最终数字或使用装饰性图片时，Track C 和 renderer 必须停止。

renderer 成功后还必须生成 `paper/argument_blueprint_trace_report.json`，并绑定
`main.tex` 与正式 writer manifest 的 SHA256。缺少或篡改该回执时，阶段转换和最终冻结均停止。

模型引导图必须声明 `task_visual_family`，并由正式契约按题型选择图形：空间/网络用
构型或拓扑，动态用轨迹，数据用变量关系，优化用可行域或目标地形，调度用资源时间图，
统计用误差或不确定性结构，评价用指标关系。`object_bindings` 必须对应图形中的真实
对象 ID、资源 lane、坐标轴变量、系列或类别；题型族、解释形式或图形类型不相容时停止。
