# 建模部分质量规则

状态：`PASS_WITH_LIMITATION / PAPER_QUALITY_LAYER_BASELINE_READY`

## 必须检查

1. 模型输入是否来自标准化数据或经审计的原始数据。
2. 决策变量、状态变量或预测目标是否定义清楚。
3. 目标函数是否明确。
4. 约束条件是否完整。
5. 参数是否有来源。
6. 求解方法是否与题型匹配。
7. baseline 与 advanced model 是否区分。
8. 启发式、评分、聚类、nearest baseline 不得写成全局最优。
9. 不可行模型不得伪造可行结果。

## 题型特定要求

| 题型 | 建模重点 |
|---|---|
| 统计分析 | 变量定义、分组口径、相关性边界 |
| 预测 | 训练验证划分、时间顺序、误差指标 |
| 优化 | 目标函数、约束、可行性、求解状态 |
| 评价 | 指标方向、权重来源、排序稳定性 |
| 图网络 | 节点边、边权、连通性、覆盖阈值 |
| 调度 | 事件流程、资源冲突、统计口径 |
| 机理拟合 | 物理假设、参数范围、残差 |

## 竞争适配与模型证据增量

以下规则属于 Track B / model-review / claim-strength 层，不是纯写作要求。

### 1. 优化与排程的最优性证据层级

1. 若结果来自 `best-found feasible`、heuristic、枚举候选或其他近似搜索，先检查能否给出 upper bound、lower bound、relaxation bound 或 `optimality gap`。
2. 能得到 bound 时，先明确目标是最大化还是最小化以及 bound 的方向，再报告 candidate 与 bound 的 gap；不能得到时，必须使用 `best-found`、`high-quality feasible` 或 `candidate` 等边界明确的口径。
3. 不强制 MILP、对偶、遗传算法、动态规划或其他复杂算法；不得为了显示数学复杂度而强塞方法。
4. 没有严格证明或全局求解器证据时，不得把候选、heuristic 或 baseline 写成全局最优。

### 2. 随机方案推荐的证据对齐

1. 对每个进入推荐理由的随机关键指标，只报告点均值不足；必须配套与设计匹配的不确定性表达。`paired difference` 不能单独作为不确定性证据，须搭配 CI、SE、bootstrap 或与设计匹配的其他明确不确定性表达。
2. 次要指标不因本条被强制做显著性检验；检查范围限于实际支撑推荐理由的指标。
3. `未显著差异` 不等于 `统计等价`。只有提供等价界限、等价检验或其他明确等价证据时，才允许使用“等价”表述。
4. 不得把“未检出显著差异”偷换成“两个方案相同”。

### 3. 随机模拟的两类稳定性

当随机推荐或核心结论依赖稳定性判断时，才必须分别评估并报告：

- `RANKING_STABILITY`：候选排序或推荐在重复、窗口、种子或合理变体下是否保持稳定；
- `ABSOLUTE_METRIC_STABILITY`：损失、产出、短缺频率等绝对数值是否已趋于稳态。

两者不得互相替代。若排序稳定但绝对指标对窗口敏感，只能形成“相对推荐稳定、绝对水平仍窗口敏感”的有限结论，不得写“已达到稳态”。若两者都不稳定，应降级推荐强度或继续模拟并扩大证据。

### 4. 信息可得性边界

`current-observable` 状态不自动构成信息泄漏。信息泄漏判断必须区分决策时点可观察的信息与决策时点不可获得的 `future-hidden` 或隐藏信息；不得把“当前可观察状态”泛化为未来信息泄漏。

### 5. 反误学边界

以下内容不得作为评分或审查标准：公式简单所以不是数学模型；优化题必须使用高级算法；所有固定题设参数都必须敏感性分析；窗口指标波动即使整个模型无效；数学复杂度本身就是竞赛质量代理。敏感性分析只在推荐高度依赖不确定或人为设定参数且具有决策价值时触发。

## 阻断条件

1. 目标函数无法定义。
2. 核心字段缺失。
3. 约束不完整却要输出正式优化方案。
4. 结果不可追溯。
