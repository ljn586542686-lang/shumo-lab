# 比赛中应急检查清单

当前状态：`PASS_WITH_LIMITATION / COMPETITION_RED_TEAM_CONTINGENCY_READY`

本清单用于比赛过程中快速判断是否继续自动流程、人工接管或降级为 baseline。

## 1. 审题异常

- [ ] 如果题型路由低置信度：立即人工审题；
- [ ] 如果漏问：补问题清单，停止扩展模型；
- [ ] 如果目标函数不清：先做统计或评价 baseline，不急于优化；
- [ ] 如果约束不完整：记录缺约束风险，避免正式结论。

## 2. 数据异常

- [ ] 文件不可读：手工转换或只抽取关键字段；
- [ ] 字段缺失：标记阻断或缩小模型范围；
- [ ] 异常值：不得静默修正，必须记录；
- [ ] 单位不明：写明假设并做敏感性；
- [ ] raw 数据污染：停止使用，恢复备份或重新获取。

## 3. 建模异常

- [ ] 模型不可行：输出不可行诊断，切到 baseline；
- [ ] 优化过慢：限制变量规模或改用启发式；
- [ ] 预测指标不稳定：只写探索性预测，不写正式结论；
- [ ] baseline 被夸大：立即改写为基准方案；
- [ ] 缺文献支撑：先保留方法说明，正式提交前补引用。

## 4. 代码异常

- [ ] 脚本报错：保留报错原因，切换最小脚本；
- [ ] 缺包：用标准库或手工计算替代；
- [ ] 路径错误：统一使用 current_case 相对路径；
- [ ] 输出缺失：补最小 result summary 和 validation note；
- [ ] 图表失败：使用 Excel 或手工图替代。

## 5. 写作异常

- [ ] 论文结构不完整：优先补摘要、问题分析、模型、结果、局限性；
- [ ] 结论无证据：删除或补证据链；
- [ ] 图表英文：改中文或换展示版；
- [ ] 引用缺失：保留引用缺口清单，正式提交前人工补齐；
- [ ] AI 披露冲突：按当前模式重写。

## 6. 工程异常

- [ ] 如果发现 `final_submit/` 异常出现：立即停止并人工确认；
- [ ] 如果 active_competition 引用历史 case：删除引用并重建证据链；
- [ ] 如果 runner/freeze/status 冲突：以人工状态源为准；
- [ ] 如果文件过多：使用公开展示过滤清单。

## 7. 时间不足

提交前 3 小时仍无稳定完整模型时：

1. 停止复杂模型；
2. 保留一个可解释 baseline；
3. 补核心图表和结果表；
4. 写清局限性；
5. 人工完成论文结构和引用；
6. 严禁新增未验证结论。
