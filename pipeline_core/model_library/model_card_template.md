# 模型卡模板

状态：`PASS_WITH_LIMITATION / PROBLEM_ROUTING_MODEL_LIBRARY_BASELINE_READY`

每个模型进入 active_competition 或正式 case 前，应至少填写以下模型卡。模型卡不是论文正文，也不是最终模型授权。

## 模型名称

填写模型名称，例如 `logistic baseline`、`线性规划`、`最短路覆盖 baseline`。

## 适用题型

说明适用的题型和子问题。

## 输入数据要求

1. 必需字段。
2. 可选字段。
3. 数据单位。
4. 缺失值处理要求。
5. 异常值披露要求。

## 输出结果

1. 输出表。
2. 输出图。
3. 关键指标。
4. 结果摘要。

## 数学假设

1. 数据独立性或时间顺序假设。
2. 线性、凸性、平稳性或可达性假设。
3. 物理或业务边界假设。

## 优点

列出该模型的可解释性、实现成本、稳定性和论文表达价值。

## 局限

列出不能覆盖的题面要求、数据依赖和理论限制。

## 验证指标

列出适用的数值一致性、预测误差、分类指标、约束可行性、覆盖率或排序稳定性指标。

## 敏感性分析

列出参数扰动、权重扰动、阈值扰动、异常值处理、缺失值处理等测试。

## 论文写法边界

1. 不得把 baseline 写成最终正式结论。
2. 不得把预测值写成真实值。
3. 不得把启发式写成全局最优。
4. 不得省略未覆盖子问题。

## 常见误用

列出常见误用，例如相关性写成因果、聚类标签过度解释、欧氏距离写成道路距离。

## 是否可作为 baseline

填写 `yes` / `no`，并说明原因。

## 是否允许声称最优

默认填写 `no`。只有在数学证明、求解器全局证明和约束完整性都满足时，才可由人工 gate 修改。
