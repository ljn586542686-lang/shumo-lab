# 题型路由器规范

状态：`PASS_WITH_LIMITATION / PROBLEM_ROUTING_MODEL_LIBRARY_BASELINE_READY`

本规范只设计路由逻辑，不实现完整算法。题型路由器的目标是给出候选题型、主辅题型、模型路线和风险边界，不直接决定最终模型。

## 1. 输入

1. 题面抽取结果：题目名称、问题数量、每问任务、输出要求。
2. 数据审计结果：文件清单、字段结构、行列规模、缺失值、异常值。
3. 约束完整性检查：目标、约束、单位、边界、模板要求。
4. 字段结构：时间字段、空间字段、类别字段、目标标签、成本或容量参数。
5. 当前 case 配置：是否 active_competition、是否 final_submit_allowed、是否需要 human gate。

## 2. 输出

1. 候选题型列表。
2. 主题型和辅助题型。
3. 推荐模型路线。
4. 推荐验证计划。
5. 推荐敏感性分析。
6. 风险边界。
7. 人工确认问题。
8. 置信度：`high` / `medium` / `low`。

## 3. 路由逻辑

| 判断维度 | 路由依据 | 示例 |
|---|---|---|
| 关键词 | 题面中的任务动词和名词 | “预测”指向预测类；“最优”指向优化类；“覆盖”指向图网络类 |
| 数据结构 | 表格、时间序列、节点边、曲线、分类标签 | 节点边表指向图网络；按周数据指向时间序列 |
| 目标函数 | 是否存在最大化、最小化、成本、收益 | 明确目标函数指向优化规划 |
| 约束类型 | 容量、预算、时间、物理边界、整数性 | 多约束指向优化或调度 |
| 输出要求 | 排序、预测表、分配方案、提交模板 | TopN 指向评价，未来计划指向预测加优化 |
| 多问结构 | 各问是否需要不同模型 | 多问递进通常指向混合型问题 |

## 4. 置信度规则

| 置信度 | 条件 | 处理 |
|---|---|---|
| high | 题面目标、数据结构、输出要求一致指向同一题型 | 可进入模型路线草案，但仍需人工 gate |
| medium | 存在主辅题型，或部分字段需要确认 | 生成多路线方案，人工确认主路线 |
| low | 题面缺失、附件缺失、目标不明或字段无法确认 | 不进入建模，先补充材料或人工确认 |

## 5. 混合型问题处理

混合型问题允许多路由，不得强行压成单一题型。路由结果应包含：

1. 主线任务。
2. 每个子问题的局部题型。
3. 子问题之间的数据交接。
4. 哪个子问题适合最小闭环。
5. 哪些子问题暂不覆盖。

## 6. 禁止事项

1. 不允许只凭题名直接定题型。
2. 不允许绕过数据审计。
3. 不允许把历史 case 模型路线直接套到新题。
4. 不允许把低置信度题型写成确定结论。
5. 不允许在缺约束状态下继续优化建模。
