# active_competition 题型路由与模型库使用说明

状态：`PASS_WITH_LIMITATION / PROBLEM_ROUTING_MODEL_LIBRARY_BASELINE_READY`

## 1. 使用流程

1. 放入 `data/raw/`：所有正式赛题材料必须放在 `cases/active_competition/current_case/data/raw/`。
2. intake 审计：生成材料清单、题面抽取、数据可用性和约束完整性检查。
3. 数据标准化：生成 `data/processed/` 与 `data/schema/`，不得修改 raw。
4. 约束完整性检查：确认目标、约束、单位、输出模板和人工确认项。
5. 题型路由：根据题面、数据结构、目标函数、约束和输出要求判断候选题型。
6. 模型路线选择：从注册表中选择 baseline 和可选 advanced 路线。
7. 最小闭环：先运行最小可验证模型，输出结果表、验证报告和证据链。
8. 验证与敏感性：检查数值一致性、输出契约、异常处理和扰动结果。
9. 论文草稿：只在结果、证据链和边界清楚后生成 DRAFT_ONLY 草稿。
10. 展示包或正式披露分流：根据使用场景选择 `showcase_mode` 或 `official_submission_mode`。

## 2. showcase_mode

适用场景：

1. 老师沟通。
2. 队员交流。
3. 暑假训练。
4. 选拔展示。
5. 阶段性成果展示包。

规则：

1. AI 使用可概括表述为“智能辅助工具”“AI 辅助工具”“辅助建模工具”。
2. 不写具体 AI 名称和具体模型名。
3. 不展示完整提示词、完整对话和底层系统实现。
4. 展示材料必须中文为主。
5. 不得写成正式比赛论文。

## 3. official_submission_mode

适用场景：

1. 正式比赛论文。
2. 正式提交附件。
3. AI 使用声明。
4. 组委会要求提交的 AI 使用记录。

规则：

1. 必须按当年竞赛规则披露具体 AI 工具名称。
2. 必须披露版本/型号、开发机构、使用日期、使用环节、生成或辅助内容。
3. 必须披露人工复核方式。
4. 必须说明队员独立完成核心建模与分析。
5. 不得用“智能辅助工具”等模糊表述替代正式披露。

## 4. 禁止事项

1. 不从 `case_01`、`case_02` 或历史 case 复制模型路线作为新题结论。
2. 不引用机制 fixture 作为真实赛题成果。
3. 不跳过人工 gate。
4. 不创建 `final_submit/`。
5. 不把 baseline 写成全局最优。
6. 不把最小闭环写成完整赛题结果。
