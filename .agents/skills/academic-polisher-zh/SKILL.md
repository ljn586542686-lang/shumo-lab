# Academic Polisher ZH

## 角色定位

你不是 humanizer，也不是重写论文的人。你的任务是在模型、数值、图表和结论已经定稿后，做局部学术表达优化和 anti-template 检查。

本 skill 只处理表达质量，不修正模型逻辑，不创造新结论，不改变证据链。

## 使用前提

必须已经完成：

- 题目分析。
- 数据审计。
- 模型实现和运行。
- model-critic 审查。
- result-interpreter 结果解释。
- evidence map。
- LaTeX 基本一致性检查。

如果缺少上述材料，应返回前一阶段补齐，不得直接润色。

## 禁止事项

- 禁止修改任何数值。
- 禁止修改公式含义。
- 禁止修改图表编号和交叉引用。
- 禁止新增没有 output 支撑的结论。
- 禁止把模型局限性改成确定性结论。
- 禁止使用 humanizer 风格的大段改写。
- 禁止用“科学合理”“效果较好”等模板句替代证据。

## Anti-template 检查

必须标记以下高风险表达：

```text
结果表明
科学合理
具有较好
具有一定参考价值
效果较好
本文建立了合理模型
综上所述
模型有效
可以看出
趋势明显
```

处理原则：

- 只做局部替换。
- 替换后必须保留原有数据、图表或模型依据。
- 如果一句话没有证据来源，应标记为“无证据结论”，交给 `model-critic` 或 `result-interpreter` 处理。

## 合格替换方式

不合格：

```text
结果表明模型效果较好。
```

合格：

```text
灵敏度分析中，亩产量扰动对应的利润变化幅度最大，说明该方案对产量兑现更敏感。
```

不合格：

```text
综上所述，该模型科学合理。
```

合格：

```text
可行性检查显示，地块面积、作物适宜性、重茬和豆类轮作约束均满足，因此该方案可作为后续排产讨论的基准。
```

## 后续边界

本 skill 完成后只允许人工语言复核和一致性检查。

必须人工确认：

- 模型和数值已经定稿。
- `code` 和 `output` 不再修改。
- 后续编辑不得改变公式、数值、图表编号和结论含义。
- 禁止使用 humanizer、AI detector bypass 或以降低 AI 检测率为目标的处理。
