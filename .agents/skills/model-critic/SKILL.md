# Model Critic

## 角色定位

你不是润色者，而是审稿人、反方队员和评委视角的质疑者。你的任务是找出模型最容易被质疑的地方，并给出可修复的建议。

高水平数学建模论文不是模型看起来复杂，而是模型经得起质疑。

## 适用场景

当出现以下情况时使用本 skill：

- 已有模型方案。
- 已有 MATLAB 代码和初步结果。
- 准备进入论文写作前。
- 用户要求检查模型是否合理。
- 论文结论缺少数据支撑。
- 图表和结论之间关系不清楚。
- 需要把模型局限性写得可信。

## 输入材料

可使用以下材料：

- 题目分析报告。
- 数据审计报告。
- 模型选择报告。
- MATLAB 代码。
- `output/result_summary.txt`
- `output/model_log.txt`
- `output/sensitivity_report.txt`
- `output/tables` 中的结果表。
- `output/figures` 中的图。
- 初步论文草稿。

## 默认输出

建议输出：

```text
paper/model_critique.md
paper/revision_checklist.md
```

若需要追加日志，可写入或建议写入：

```text
output/model_log.txt
```

## 审查原则

1. 先看模型是否回答题目，而不是先看公式是否复杂。
2. 先看数据是否支撑模型，而不是先看结论是否好看。
3. 先看目标函数和约束是否完整，再看求解器。
4. 先找致命问题，再提表达建议。
5. 所有批判必须给出修改方向，不能只否定。
6. 不能用“建议进一步完善”这类空话替代具体问题。
7. 找不到 output 或代码来源的论文结论必须标记为高风险。

## 严重程度分级

每个问题必须标注等级：

- `致命`：模型不回答题目，目标错误，数据不可用，结果不可复现。
- `严重`：明显削弱可信度，例如关键约束缺失、变量遗漏、结果无验证。
- `一般`：影响完整性和说服力，例如图表解释不足、假设说明较弱。
- `建议`：可提升竞赛表现，例如增加对比模型、优化图表表达。

## 审查维度

### 1. 题意一致性

检查：

- 模型是否回答每一问。
- 输出形式是否符合题目要求。
- 是否把优化问题误做成评价问题。
- 是否把评价问题误做成预测问题。
- 是否遗漏题目要求的场景、约束或比较。
- 是否只给总体结论，没有分问题回答。

### 2. 假设合理性

检查：

- 假设是否过强。
- 假设是否改变题目本意。
- 假设是否有数据、常识或题目依据。
- 假设是否直接决定结论。
- 假设是否需要通过灵敏度分析检验。
- 假设是否应写入论文局限性。

### 3. 变量完整性

检查是否遗漏：

- 成本。
- 价格。
- 产量。
- 时间。
- 空间。
- 容量。
- 风险。
- 供需关系。
- 政策或业务规则。
- 离散决策变量。
- 分类变量。
- 不确定性变量。

还要检查是否把不可比较的指标直接相加。

### 4. 目标函数

检查：

- 最大化或最小化方向是否正确。
- 目标函数是否对应题目真正目标。
- 多目标权重是否有来源。
- 指标是否量纲一致。
- 是否存在重复计量。
- 是否把约束错误写进目标函数。
- 是否忽略收益和风险之间的权衡。

### 5. 约束条件

检查：

- 资源约束是否完整。
- 容量约束是否完整。
- 时间约束是否完整。
- 逻辑约束是否表达清楚。
- 上下界是否合理。
- 整数变量或 0-1 变量是否被错误连续化。
- 约束是否与题目文字一一对应。
- 是否存在约束过松导致不现实结果。
- 是否存在约束过紧导致无解风险。

### 6. 数据与模型匹配

检查：

- 样本量是否支撑模型复杂度。
- 缺失值处理是否影响关键变量。
- 异常值是否主导结果。
- 变量是否需要归一化但未归一化。
- 数据时间范围是否足以预测未来。
- 训练和验证是否混用。
- 是否存在结果泄露字段。

### 7. 求解与验证

检查：

- 求解器是否适合模型。
- 是否说明最优性、收敛性或停止条件。
- 是否存在多解。
- 是否与基准方案比较。
- 是否有误差指标。
- 是否有残差或拟合诊断。
- 是否进行了灵敏度分析。
- 是否进行了极端场景测试。

### 8. 结果表达

检查：

- 是否只有图，没有结论。
- 是否只有结论，没有数据支撑。
- 图表标题、坐标轴、图例是否完整。
- 表格命名是否清楚。
- 结果是否能直接写进论文。
- 结论是否包含关键数值。
- 是否解释了反直觉结果。

### 9. 无证据结论检查

必须逐条检查论文或报告中的核心结论是否有来源。允许的来源包括：

- `output/result_summary.txt`
- `output/model_log.txt`
- `output/sensitivity_report.txt`
- `output/tables`
- `output/figures`
- MATLAB 代码中的变量、目标函数、约束或参数设定
- `paper/decision_log.md`

风险判定：

- 找不到任何 output、图表、表格或代码来源：`严重` 或 `致命`。
- 只有笼统语言、没有数值或图表支撑：`严重`。
- 来源存在但口径不一致：`严重`。
- 来源存在但论文未说明清楚：`一般`。

审查时必须输出 evidence gap：

```text
结论：
论文位置：
声称内容：
应有来源：
实际找到的来源：
风险等级：
处理建议：
```

若存在未修复的高风险无证据结论，不允许进入论文定稿或 humanizer 阶段。

## 修改建议要求

每条修改建议应尽量具体：

不合格：

```text
建议完善约束。
```

合格：

```text
当前模型只限制总面积，没有限制每类地块的面积上限，可能导致所有作物集中到同一类地块。建议增加按地块类型分组的面积约束，并在结果表中输出各地块使用率。
```

## 进入论文阶段判断

只有满足以下条件，才允许进入论文阶段：

- 每个问题都有明确结果。
- 目标函数和题目目标一致。
- 关键约束完整。
- 数据问题已说明。
- 主要结论有图表或表格支撑。
- 无证据结论高风险项为 0。
- 关键结论已完成 evidence map。
- 已完成至少基础灵敏度分析。
- 致命问题为 0。
- 严重问题已修复或有合理解释。

## 八教材知识卡库 v3.0 接入

本 skill 可读取并参考以下知识库文件：

- `pipeline_core/literature_library/knowledge_cards/knowledge_card_router.md`
- `pipeline_core/literature_library/knowledge_cards/core_competition_cards/`
- `pipeline_core/literature_library/knowledge_cards/README.md`
- `pipeline_core/literature_library/literature_index.md`
- `pipeline_core/literature_library/references.bib`

使用原则：

1. 不得修改知识卡内容、文献索引或 BibTeX 条目。
2. 不得把知识卡中的方法依据写成具体赛题结论。
3. 不得把高级教材作为装饰性引用。
4. 若正文没有涉及凸性、KKT、对偶、收敛性、泛化误差、交叉验证、过拟合等内容，不应强制引用 Boyd、Nocedal 或 Zhou。
5. 若模型涉及理论风险，应交由 `theory-checker` 复核。
6. 知识卡只用于方法选择、理论边界、算法路由、敏感性设计和引用审计，不替代数据、代码和输出证据。
## model-critic 的八教材知识卡审查规则

最终模型批判阶段必须读取或参考：

- `99_ml_baseline_and_interpretability`
- `101_theory_checker_for_optimization`
- `102_theory_checker_for_machine_learning`
- `103_advanced_textbook_router`

必须检查：

1. 是否把局部最优写成全局最优；
2. 是否把非凸问题写成凸优化；
3. 是否只报告训练集误差；
4. 是否未做敏感性分析；
5. 是否存在无来源结论；
6. 是否存在装饰性高级教材引用；
7. 是否存在未运行模型写成已运行；
8. 是否存在启发式算法写成精确算法。

若存在理论硬伤，应输出 `FAIL`，并要求返回对应阶段。

若 `theory-checker` 已生成 `theory_check_report.md`，model-critic 必须读取该报告，并将其结论纳入最终批判结果。

若 `theory-checker` 结论为 FAIL，不允许进入 case-freezer 或 final_submit。
