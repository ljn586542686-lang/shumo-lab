# Theory Checker

## 定位与边界

对当前 case 中已经提出的理论主张做证据化复核，区分“定义”“建模假设”
“数值迹象”和“已经证明的结论”。本 skill 默认只读；只有用户明确要求落盘且
当前阶段允许时，才写入当前 case 的
`output/validation/theory_check_report.md`。

禁止：

- 生成或替换模型路线、算法、代码、实验结果和论文正文；
- 自动修改 `human_review/`、自动通过 Gate 或改变 pipeline 状态；
- 把知识卡、单次数值计算、求解器成功或示意图当作数学证明；
- 在 case 不明确时把报告写到根目录；
- 未经授权运行 MATLAB，或创建 `final_submit/`。

在 Gate 2 前审查候选路线时，只判断该路线的关键理论前提是否成立。发现关键
前提未证，不替路线补机制，报告 `FAIL` 并建议保持 Gate 2 阻断。

## 输入

先确定唯一的当前 case，再按实际存在情况读取：

- `problem_contract.md`、`problem_analysis.md`、`case_config.json`；
- `model/model_formulation.md`、`model_routes.md`；
- `human_review/gate_2_model_choice.md`；
- 路由和 handoff 文件；
- 已存在的公式、代码、输出、验证报告、`evidence_map.md` 和论文片段。

只在相关理论确实需要时读取知识卡。知识卡可以给出审查线索和适用条件，不能
代替当前模型的推导。找不到对应知识卡时，标记 `NO_RELEVANT_CARD`，不得强行
注入无关材料或全库搜索当前赛题答案。

## 核心审查流程

### 1. 建立理论主张清单

逐条记录需要复核的精确主张、所在文件和行号，以及它对路线可行性、Gate、
结果或论文结论的影响。不要把多个不同主张合成一句模糊结论。

每条主张只能使用以下证据状态：

- `PROVED`：已有可复核的解析推导或满足前提的正式定理应用；
- `DISPROVED`：与定义、维数、反例或已确认约束矛盾；
- `NOT_PROVED`：证据不足，或只有数值迹象、经验结果、待运行检查；
- `NOT_APPLICABLE`：当前模型不需要该主张。

数值秩、随机试验、仿真成功或若干样例成立不能写成解析意义的 `PROVED`。
但当路线只主张“给定构型和明确邻域内的条件性局部可行”，并且已经锁定构型、
容差、退化守卫、差分交叉校验和失败条件时，这类证据可以支持
`WARNING / ELIGIBLE_FOR_CONDITIONAL_IMPLEMENTATION`，不得错误升级为要求全域解析证明。

### 2. 核对假设与题面来源

- 区分题面事实、建模选择、算法条件和待验证条件；
- 检查一个子问题的条件是否被非法外推到另一个子问题；
- 检查噪声、独立性、可控位移、锚点坐标、初始邻域等条件是否有来源；
- 对未由题面给出的必要条件，要求显式标为建模假设并说明影响。

### 3. 核对变量维数、对称性与规范自由度

涉及可辨识性、几何定位、图刚性或 Jacobian 秩时，必须明确：

1. 状态空间及其维数 `n`；
2. 观测映射 `H` 的定义、行数和独立约束来源；
3. 保持观测不变的变换群及轨道维数 `g`；
4. 哪些平移、旋转、尺度或镜像自由度已被锚点/坐标选择消除；
5. 当前变量参数化下的期望局部秩 `n-g`；
6. Jacobian 的实际列数、候选零空间基和秩判据。

规范自由度只能扣除一次。若变量已经相对固定锚点表示，不得再次把已消除的
平移自由度计入零空间。维数账不一致时，相关秩主张为 `DISPROVED`，不能仅靠
改写目标秩数字通过。

### 4. 核对局部可辨识性、分支与轮换覆盖

- Jacobian 满秩只能支持相应正则条件下的局部结论，不能自动推出全局唯一；
- 必须检查离散镜像、编号置换、周期角度和退化构型等分支；
- 若用初始邻域排除分支，必须给出该邻域的定义或可验证判据；
- 多轮观测必须说明累计 Jacobian/约束如何覆盖全部待估方向；
- “每架最终都参与过”不等于累计约束独立，也不等于整体刚性。

若方案使用主动探测位移估计二维位置梯度，单个方向的 `+delta v/-delta v`
只给出一个方向导数。必须证明同轮或跨轮的探测方向张成二维空间，例如两条
线性无关方向；否则完整二维局部校正机制为 `NOT_PROVED`。

### 5. 按模型类型补充检查

只执行与当前主张有关的项目：

- 优化：目标/约束、可行性、凸性、KKT 前提、局部与全局最优边界；
- 非线性数值法：初值、停止准则、多起点、约束违反和收敛声明；
- 统计估计：可辨识性、误差模型、独立性、样本来源、区间和残差；
- 机器学习：数据泄漏、训练/验证/测试划分、基线、训练外指标和泛化边界；
- 动力系统：平衡点、稳定性条件、离散化误差和收敛范围；
- 几何/图模型：退化构型、刚性类型、锚定条件、镜像和全局唯一性。

### 6. 形成结论

总体状态只使用：

- `PASS`：所有影响当前阶段放行的关键主张均为 `PROVED` 或
  `NOT_APPLICABLE`，且无矛盾；
- `WARNING`：未形成全局解析证明，但当前主张已明确降为条件性局部结论，且
  构型、数值交叉校验、适用邻域和 fail-closed 守卫足以支持下一步受控实现；
- `FAIL`：关键主张为 `DISPROVED`，或路线仍依赖未限定且无验证计划的
  `NOT_PROVED` 主张，或者假设来源、维数账、局部/全局边界存在会改变路线
  可行性的错误。

`PASS` 不是 human Gate approval。任何状态都不得直接修改 Gate 文件或 pipeline
状态。

## 输出格式

在聊天或获准写入的报告中使用：

```markdown
# Theory Check Report

THEORY_CHECK_STATUS: PASS | WARNING | FAIL
GATE_RECOMMENDATION: KEEP_PENDING | ELIGIBLE_FOR_HUMAN_REVIEW

## 理论主张
| ID | 主张与来源 | 前提 | 证据 | 状态 | 影响 |
|---|---|---|---|---|---|

## 维数与规范自由度账
| 对象 | 数值/定义 | 证据位置 |
|---|---|---|

## 阻断项
- ...

## 非阻断风险
- ...

## 最小修复方向
- 只说明需要补什么证明、反例或假设，不代写新路线。
```

所有结论必须带文件路径和行号，或明确写出“当前材料未提供”。不能因为报告
模板存在就宣称审查已经运行。
