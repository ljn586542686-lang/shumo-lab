# 赛时功能对照表

比赛时用到的功能按使用者要做的事分成 **34 项**。其中 **22 项在公开代码上跑过，10 项要补齐数据、工具或授权才能完整使用，2 项只有说明**。下表每行算一项，用到的脚本、测试和知识卡算在同一行。前 32 项都能找到相应的代码或操作入口。为演示另写的弹簧例子单独列在下文。

标为“实测”的项目，都在干净副本中运行过表里写明的步骤。标为“条件”的项目，有些需要原始输入或外部工具，有些要请人独立审稿或签字授权。要找对应测试，可以从仓库根目录搜索最后一列的名称。

## 如何确定赛时版本

- 最初的开发仓库 `MathModeling2026` 停在 `master` 的 `7d14e86`，有未提交内容。该检出的活动案例目录以说明和占位为主。
- 9 月 9 日的赛前最终状态记录、分支和工作树共同指向 `MathModeling2026_contest_ready`，基线为 `precontest/freeze-20260909` 的 `49eb3d22f4522126809096b1a81154a1f8cb24e4`。当时记录为 989 项通过、6 项跳过。这个数只描述赛前基线。
- 赛时工作树后来有未提交改动。此次按实际文件纳入 `model_authority.py` 中结果接受后的再授权逻辑、`problem_type_router.py` 的显式题意路径以及相应路由测试。正式案例的求解入口确实调用了再授权逻辑。储能的逐日代码来自活动案例；Q4 的运行与核表脚本还从工作树的 `tmp/` 找回。活动案例交接最终可见 `TRACK_C`、修订号 10。单一 Git 提交无法标识全部赛时内容，这些线索也不足以证明最终交付已获批准。
- 独立的弹簧标定例子先于交互示例完成。为方便读者跟着做，后来又写了 `examples/spring_workshop.py`、`examples/spring_steps.py`、合成回归测试和使用说明。弹簧题目、两种备选解法和评分是教学材料，选择算法的注册表、阶段推进、人工确认、建模交接、评分表写入和 TeX 排版沿用比赛时的程序。知识库第 28 号卡保留原路由标识，例子改成了步行通勤用时。第 103 号卡补充了调用规则的适用场景。弹簧示例从命令行运行。

## 哪些材料可以在这里找到

| 材料或能力 | 处置与原因 |
| --- | --- |
| 真题题面、附件、试算、正式日账本、原论文和结果图表 | 留在私有侧。公开提供数据接口、空模板和合成材料，可以检查计算方法而无需取得赛题文件。 |
| 真实签名、例外审批、私人会话、参赛身份与账号 | 留在私有侧。审核人填写空模板、独立决策；Q4 不附真实例外放行脚本。 |
| Q2—Q4 正式回放与排障 | 保留预测修正、每日求解、输入读写、日期与状态延续、验证和报表接口；真实起始荷电量、绑定私有预测版本的加载器、针对具体日期和结果的特判、修订记录以及原结果表留在私有侧。Q4 原脚本中的真实初值改为调用者显式提供，年度执行须核对授权。 |
| 第三方教材正文、论文、受限样例及原版提交表格 | 保留项目自撰方法卡、通用知识卡、书目元数据、引用资格检查和表格读写程序。原教材章节、完整第三方文件及其私有索引未随仓库分发。部分原索引中的拓展阅读需另行取得。 |
| 历年完整训练案例、专用对抗场景和恢复包 | 保留通用路由、适配契约、复核和阻断测试。案例附件、场景专用操作实现及历史输出未收录。养殖排程适配器仍能报告缺失的上游材料。 |
| Git 历史、本地缓存和私有运行授权 | 仓库提供隔离运行和校验来源的代码。要验证自己案例的 Git 来源，需要使用自己的提交记录。 |
| 弹簧教学示例 | 程序核对输入、结果和图表后，把标定数值填入教学说明，按模板排版。正式论文的结构、公式、图表与授权路径由专门回归测试覆盖。 |

审批表和外部审稿记录留给使用者按实际情况填写。原创代码的授权范围见[项目说明](../README.md)。
