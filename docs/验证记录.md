# 验证记录

验证时先把要发布的文件复制到一个空目录，把 Python 模块搜索路径指向这份副本，再从里面运行示例和测试。这样可以检查读者拿到的文件能否独立运行。赛题附件和真实授权文件留在原工作区。需要 Git 提交记录的测试会在临时目录里自己建仓库。

## 完整测试命令与 Windows 首测结果

```powershell
python -m pytest -q -rs -p no:cacheprovider pipeline_core/tests math_core/tests validation/tests quality_gates/tests examples/storage/code/python/tests
```

**1267 项通过，0 项失败，6 项跳过；另有 82 个子测试通过。** 跳过项为 1 项需显式启用的真实 MATLAB 出图、4 项本机权限不支持的 Windows 符号链接测试、1 项本机文件系统禁止星号文件名的测试。Python 侧 MATLAB 接口与图像复核另有通过记录。赛前基线的 989 项通过是历史数字，未计入本次统计。

弹簧示例实际运行了拟合与复算，并把结果排入预先写好的标定记录。回归测试使用的审批输入只用于验证解析器和状态边界；交付目录中保留空白审批模板。外部 AI 会话、真人红队意见、年度赛题回放、正式签署和公开推送均未计入实测结果。

## 文件完整性

`SHA256SUMS` 记录了仓库里除清单自身以外每个文件的摘要，路径从仓库根目录算起。发布时 `cases/` 只含模板。案例模板和储能配置从 `CASE_INTAKE`、修订 0 开始，人工确认状态为 `PENDING_MANUAL_REVIEW`，提交开关为 `locked`。当时的文本扫描未发现常见凭据格式或用户主目录的绝对路径。Git 测试中的邮箱使用示例域名。
